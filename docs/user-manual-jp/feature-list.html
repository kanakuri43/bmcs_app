機能一覧

このページでわかること　このシステムにどんな機能があるか、どんなときに使うか。また、市販の一般的な販売管理ソフトと考え方が違うところ。

機能はメインメニューの分類ごとに並べています。「操作説明」を押すと、その画面の操作のしかたのページに移ります。画面の画像をクリックすると、拡大して表示します。

画面は開発用データの表示例で、実際の得意先・金額とは異なります。

1お客様は2種類

お客様（得意先）は2種類に分かれ、請求と入金のしかたが違います。どちらにするかは得意先マスタの登録のときに決め、後から変えられません。

種類主なお客様請求入金
締め取引（締め得意先）民間企業20日締め・末日締めなどの締め日で、1か月分をまとめて請求書を出します（請求締め処理）古い請求から自動で消し込みます（入金入力）
都度請求（都度得意先）学校・官公庁など締めは行わず、納品1件〜数件ごとに請求書を出します（明細請求書発行）売上や請求書を指定して消し込みます（明細入金）

このシステムで扱うのは「受注 → 売上 → 請求 → 入金 → 元帳 → 月次締め」です。在庫・発注・仕入伝票・買掛・支払は扱いません。ただし仕入先と仕入先ごとの原価は登録でき、粗利の計算に使います。

★印は、一般的な販売管理ソフトと考え方が違う機能です。どう違うかは3章で説明します。

3一般的な販売管理ソフトとの違い

ここでいう「一般的なソフト」は、中小企業向けの市販の販売管理ソフトによくある作りのことです。製品によって違うので、よくある傾向として比べています。

3-1. 締め請求と都度請求を、別々の流れで持っている

一般的なソフト月1回の締め請求が基本で、都度請求は「締め日を『都度』にしたお客様」として、同じ仕組みで扱うことが多いです。
このシステム締め取引と都度請求で、請求・入金・消込の仕組みそのものを分けています。
  • 締め取引のお客様は、請求締めで請求を確定し、入金はその請求に充てます。
  • 都度請求のお客様は締めをしません。売上明細を選んで明細請求書を出し、入金は明細ごとに消し込みます。
  • 都度請求のお客様の税区分は「内税明細単位」と決まっています（得意先マスタで、締め日との組み合わせをチェックします）。

学校・官公庁のように「この納品の分だけ請求書がほしい」「入金も納品ごとに来る」お客様を、締め取引のお客様と同じように正確に管理するための作りです。

3-2. 明細請求書は、売上明細を選んで、宛名を変えて出せる

一般的なソフト都度請求は「売上伝票1枚＝請求書1枚」で、宛名は得意先マスタの名前のまま、ということが多いです。
このシステム
  • 未請求の売上を明細の行ごとに選べます。何枚かの伝票の明細を1枚の請求書にまとめることも、1枚の伝票の明細を別々の請求書に分けることもできます。
  • 選べるのは「未請求で、入金もまだ」の明細だけです。入金済みの売上は、請求書を出していなくても選べません。
  • 同じ明細が2枚の請求書に載ることはありません（データベースでも防いでいます）。
  • 出した請求書は取り消せます。取り消すと売上は未請求に戻ります（入金済みのものは取り消せません）。
  • 宛名は出すたびに書き換えられます（3-3）。

3-3. 宛名は伝票ごとに書き換える（クラスや先生ごとにお客様を分けない）

一般的なソフト学校のクラスや先生ごとに請求書を分けたいときは、お客様を細かく分けて登録するか、「納品先」「請求先」を別に登録することが多いです。
このシステム学校・学年・クラスのように分かれていても、得意先マスタは1件のままにします。伝票を入力するときに得意先名の欄を書き換えて、宛名にします（受注・売上・明細請求書・入金の各画面でできます）。
  • お客様が細かく分かれないので、残高・元帳・分析は学校単位でまとまったままです。
  • 宛名を書き換えても、代表者を印字するかどうかは得意先マスタの設定のままです。
  • 同じように、明細の商品名も書き換えられます。書き換えた商品名の最後には「.」が付くので、マスタの名前のままの行と見分けられます。

3-4. 本社にまとめて請求するときは、残高・入金も本社にまとめる

一般的なソフト「請求先」を指定して、支店の売上を本社あての請求書に載せる機能があることが多いです。
このシステム請求書だけでなく、残高・入金・元帳も、まとめる先（請求集約先。例：本社）に一本化します。
  • 請求・入金・売掛残高は、まとめる先にだけ持ちます。まとめられる側（請求集約元。例：支店）で入金を入力しようとすると、エラーになります。
  • まとめられる側の得意先元帳は、売上の履歴だけを表示し、残高は表示しません。「請求・残高はまとめる先にまとめられています」と案内が出ます。
  • 請求書には、まとめられる側のお客様ごとに、見出し・明細・小計を分けて印字します。
  • 締め日・税区分・端数区分がまとめる先と違う、都度請求のお客様をまとめる、3段以上にする、といった設定はできません。
  • 請求締めをした売上が1件でもあるお客様は、まとめる先を変えられません。

3-3の「宛名の書き換え」とは別の仕組みです。

3-5. 消費税は、お客様ごとの税区分どおりに、インボイスのルールで計算する

一般的なソフト消費税の計算のしかた（伝票ごと・請求ごと・明細ごと）と端数処理を、お客様ごとに選べるものが多いです。ただし、後から設定を変えられることが多いです。
このシステム
  • 税区分（請求単位／伝票単位／内税明細単位）・端数区分・締め日は、お客様を登録した後は変えられません。変えられると、過去の伝票の消費税を同じ金額で計算し直せなくなり、請求の金額が合わなくなるためです。
  • 端数処理は「標準・軽減の区分と税率の組み合わせ」ごとに1回です。税率が変わる前後で、軽減税率と古い標準税率が同じ%になっても、混ざりません。
  • 返品・値引（マイナスの金額）は、プラスのときと同じ丸め方をしてからマイナスにします。同じ金額の返品・値引で、元の売上の消費税がぴったり打ち消されます。
  • 明細の金額（数量×単価）も、お客様の端数区分で1円単位にしてから保存します。
  • 伝票には、登録したときの税率を記録します。後で税率マスタが変わっても、登録済みの伝票の消費税は変わりません。その期間の伝票がある税率は、税率マスタで変えられません。
  • 請求書・明細請求書は、インボイス（適格請求書）に必要なことを印字します。税率ごとの金額と消費税は確定した値として保存するので、印刷し直しても同じ金額になります。

3-6. 訂正は「赤黒」ではなく元の伝票を直す。締め・入金で自動的に直せなくなる

一般的なソフト締めた後の訂正は、マイナスの伝票（赤伝）と正しい伝票（黒伝）を作って行うことが多いです。
このシステム訂正・取消は元の伝票をそのまま直します。そのかわり、次のどれかに当たる売上は直せません。
  1. 請求締めで締めた請求に入っている
  2. 明細請求書を出している
  3. その月の月次締めが済んでいる
  4. 入金で全額消し込まれている
  • 直せるかどうかは、締めや入金の状態からその都度判断します。締めを解除すれば、自動的に直せるようになります。
  • 締めの解除（請求・月次）は管理者だけが使える、別のメニューにしています。
  • 締めを解除しても請求のデータは消さず「解除済」として残し、いつ誰が締め・解除したかがわかります。締め直すと、新しい請求番号で作り直します。
  • 締めの順番が逆になる操作はできません（新しい月を締めた後に古い月を締める、古い月から解除する、など）。
  • 請求を締めた期間に、新しく売上・入金を登録することもできません（日付を締めた期間に変える訂正も同じです）。月次締めをした月も同じです。
  • 取り消した伝票は消さずに、取消済みとして残ります。

3-7. 締め取引の入金は「どの請求に充てたか」を見せず、残高だけを見せる

一般的なソフト入金を入力するときに、どの請求（または売上）の入金かを選ぶものが多いです。
このシステム
  • 締め取引のお客様の入金は、充てる先を選びません。保存すると、古い請求から順に自動で充てます。画面には残高だけを表示します。大事なのは「どれに充てたか」ではなく「いくら残っているか」だからです。
  • 都度請求のお客様の明細入金は逆に、売上明細か明細請求書を指定して消し込みます。両方を指定したときは、売上明細の指定を先に使います。
  • 消し込みの状態（未消込／一部消込／消込完了）は、入金のデータから毎回計算し直します。入金を訂正・取消すると、売上の消し込みの状態も自動で戻ります。
  • 多くもらった入金・前受けの入金は入金のほうに残り、売上の金額を超えて消し込まれることはありません。
  • 振込手数料の差額は手で入力する方針で、自動計算はしません（入力する画面はまだありません）。

3-8. 残高は得意先元帳が正しく、残高を保存しない

一般的なソフト毎月の繰越残高を保存し、そこに当月分を足し引きして残高を出すことが多いです。
このシステム
  • 残高はどこにも保存せず、表示するたびに、すべての期間の売上・入金から計算します。後から過去の日付の伝票が入っても、残高が食い違いません。
  • 請求単位のお客様は、売上を入力した時点では消費税が決まりません。そのため元帳には、消費税を別の行として入れます（締めた期間は確定した消費税、まだ締めていない期間は仮に計算した消費税）。
  • 月次締めの月末残高は、元帳で計算した残高をそのまま確定します。

3-9. 請求締めと月次締めが別になっている

一般的なソフト締めは1種類で、月の確定は「末日締め」の請求締めで兼ねることが多いです。
このシステム
  • 請求締め：お客様の締め日（20日など）ごとに、請求書を出すための締めです。
  • 月次締め：すべてのお客様（都度請求のお客様も含む）を、1日〜末日で区切って月末の売掛残高を確定する締めです。確定した月の伝票は直せなくなります。
20日締めのお客様でも、月末の残高を確定できます。

3-10. 単価と原価の決まり方

一般的なソフトお客様ごとの単価や掛率を登録できるものは多いですが、原価は商品に1つ、ということが多いです。
このシステム
  • 商品を選んだときの単価は、次の順に、最初に見つかったものが入ります。どれも手で直せます。
    1. そのお客様の特別な単価
    2. 定価 × そのお客様の掛率
    3. 商品マスタの単価（内税のお客様なら税込の単価）
  • 原価は仕入先ごとに登録できます。商品検索では同じ商品が仕入先ごとに別の行で並び、選んだ行の仕入先と原価が伝票に入ります。売上・粗利分析では、仕入先別の粗利も見られます。
  • 返品は原価もマイナスにします（元の売上の粗利を打ち消すため）。値引は原価0にします（物が動かないため）。
  • 商品検索の「過去に売ったものから」では、そのお客様に以前売ったときの単価をそのまま使えます。

3-11. 石山商店の業務に合わせた機能

  • コピー機売上CSV取込：コピー機の使用料（モノクロ・カラーの枚数）を、メーカーのCSVからそのまま売上にします。CSVの列は見出しの名前で探すので、列の並びが変わっても取り込めます。
  • 納品書の3枚つづり印刷：ミシン目で3つに分かれたA4用紙に、「納品書（控）」「請求書」「納品書」を同じ内容で印字します。複写式の伝票のかわりに、切り分けて渡します。左はしのパンチ穴に字がかからないよう、印字の位置をずらしています。

3-12. 操作・使い方

  • ログインの画面が無い：デスクトップの起動用ショートカットに社員コードを入れておき、その人が使えるメニューだけを表示します。
  • キーボードだけで操作できる：Enter で次の欄へ進み、Space で検索画面を開き、一覧は矢印キーと Enter で選びます。伝票No.の欄を空のまま Enter で新しい伝票、番号を入れて Enter で登録済みの伝票を呼び出します（共通のキー操作）。
  • PDFのために別のソフトが要らない：PDFは Windows に入っている機能で作ります。
